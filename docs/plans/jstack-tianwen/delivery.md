## 1. 已确定的产品方向与采用的技术默认

用户已明确：jstack 是一等公民与主工作流；Keel 后台自动运行；所有系统生成的人工请求先过天问；天问按不同项目的决定代答，无把握才升级。

本方案采用的默认选择：

- 一个 owner、多个明确登记的项目；先用现有 PostgreSQL 承载队列、租约、决策与全文/关键词检索。
- jstack 包和协议固定版本，原始决定持久化，摘要作为读模型；授权独立维护。
- 主流程直接使用 jstack 路线/门禁；旧状态机保留给旧任务，不双重编排。
- 普通可逆选择允许天问默认决定；高影响本身不是强制人工条件，明确授权可覆盖。授权边界变更只能由真实用户确认。
- 人工等待默认不自动弃单、不因沉默批准；仅阻塞依赖节点。
- 完成目标建议首发用 `pr_ready`；自动合并/部署有独立完成目标和明确授权，不能偷偷替换。

技术默认需要在实现中评审与验收；本文件不是部署、合并、删数据或新费用额度的授权。

### JT-01：jstack 原生只读任务，经天问建议、人工答复后可恢复

**阻塞**：无。

**交付**：Keel 接收调查任务，绑定 jstack 工作流包，由 jstack route 选择只读路径；遇到问题时落统一请求，天问生成带依据的建议，用户答复后自动恢复并产出带来源的调查结论。先用影子模式，任何结论不产生外部写操作。

**同时包含**：jstack managed 导出/DecisionProvider 的最小协议与构建分发、Keel 新任务/阶段实例、请求/attempt/actor、checkpoint、人工队列、答复唤醒、只读天问模型接线、现有任务查询兼容。

**验收**：提问前崩溃/答复后崩溃均可恢复；问题 ID 稳定；每个人工请求先有真实 Tianwen attempt；失配协议或缺 provider 在启动期拒绝；旧任务仍走旧驱动。

### JT-02：已有决定与可逆默认可代答，低风险任务自动产出 PR

**依赖**：JT-01；前置验收已满足。

**交付**：对有明确目标的单 ticket 改动，读取项目内已确认决定；天问直接解决偏好/设计问题，在授权的隔离工作区修改、验证、评审，Keel 通过受控网关创建真实 PR 并等待目标 SHA 的 CI。对未授权动作天问先提出建议再升级。

**同时包含**：最小项目决定记录、确定性接纳器、来源/范围检查、E3/E1 路径、基本委托策略、动作意图/outbox、工具凭据隔离、准确 completion target。

**验收**：一条真实小任务无逐次人工确认走到 `pr_ready`；能导出答案/授权/证据链；不能用模型自信、旧批准或模拟 CI 放行；重复投递只复用一个 PR。

### JT-03：项目记忆整理、增量检索、纠正与摘要回滚

**阻塞**：JT-02。

**交付**：多个项目的天问应用各自历史；按配置生成版本化摘要；摘要落后、决定撤销、用户纠正时即刻停止使用旧结论；只在必要时检索少量原文。用户可把一次答案明确设为本项目后续规则。

**同时包含**：项目/用户级范围、决策索引、supersede/revoke、epoch、水位与增量、摘要候选评测/发布/回滚、完整 Context 引用、导入记录的来源等级管理。

**验收**：项目 A/B 的相似问题给不同正确答案；旧摘要与回滚均不能复活撤销记录；没有静默把推断升级为用户确认；跨项目诱饵无法进入模型；检索有预算和日志。

**同时包含**：工作流依赖闭包、图版本/校验、provider 结果契约、managed pstack 副作用接管、关票/归档幂等、门禁证据失效条件、实例与旧状态投影区分。

### JT-05：天问按常驻授权代批，人工覆盖可阻止尚未执行的动作

**阻塞**：JT-03、JT-04。

**交付**：对 must-stop/审批类问题，天问先处理；在明确授权及证据范围内可代批，否则给用户一次可复用授权建议。用户覆盖、取消、暂停或撤销权限后，自动 worker 不能拿旧答案继续执行。

**同时包含**：jstack must-stop 的正式协议变更、DelegationPolicy 版本/范围/身份、受控 ExecutionPermit、fence、CAS、人工覆盖事件、paused/human 恢复入口、允许自动合并/部署时的真实适配。

**验收**：精确匹配的高影响授权可自动使用；越界/过期授权被拒；旧 worker、旧 SHA、授权撤销都不能生效；已经发往远端的动作进入回查/补偿，不能报作已撤销；天问不得修改自身授权。

**实现进展**：permit 绑定策略版本、项目授权 epoch、任务控制代次、预算快照与可选
决定 revision/决议；动作开始前、permit 后与 push 后创建 PR 前统一复核。新增
`ticket-pause/cancel/resume/override` 与 `policy-list/publish/revoke`；暂停/取消
会立即阻断未开始 outbox、撤销 `VALID` permit、递增控制代次并取消等待中的请求。
must-stop 先进入天问，只有精确委托才能代批；停止选项转 `CANCELLED`。已经
`EXECUTING` 的动作只记录外部边界，成功结算也不会把 `PAUSED` 自动改回 `PR_OPENED`。
`max_attempts` 已按 outbox 认领次数校验；token/cost 预算仍明确拒绝自动许可。

### JT-06：统一后台服务、故障恢复和备份演练

**阻塞**：JT-04、JT-05。

**同时包含**：持久队列公平调度、租约/fencing、资源上限、退避/死信、信号退出、无副作用的健康检查、指标/审计、数据库与包/blob 的一致性备份、恢复脚本和手册。

**验收**：注入进程 SIGKILL、数据库短断、模型超时、GitHub 响应丢失、重复 webhook；没有丢请求或盲重试破坏性操作；恢复备份可以继续等待问题，凭据缺失时明确停住。

**本次实现**：`keel serve` 统一承载 ingress、managed、memory、maintenance、
outbox、checks；角色健康与原因码写入 `worker_health`，`service-status` /

外部动作。确定性测试覆盖组件故障隔离、退避、信号收尾、健康无副作用、公平调度

## 3. 项目接入与授权初始化

一次接入完成：项目 ID/仓库映射 → 固定 jstack 包与配置 → 读取现有文档/ADR/明确用户答复 → 整理待确认的初始决定与授权 → 用户批量确认范围 → shadow/自动模式。

导入文档默认是 `imported_candidate`；管理员选择可信来源并确认其适用范围后，才能成为可代答依据。不能把仓库任意注释当作用户授权。初始没有历史记录时，在基本授权内采用可逆默认，真正影响目标的缺口由天问合并一次询问。

项目配置示意（目标接口，当前不支持）：

```yaml
project: project-a
workflow:
  id: jstack
  package_digest: <管理员校验的完整摘要>
  mode: managed
  completion_target: pr_ready
decisions:
  provider: tianwen
  delegation_policy: <用户确认的策略版本>
  memory_profile: <本项目摘要配置>
  uncertainty: escalate_after_bounded_investigation
runtime:
  max_running_stages: 4
  fairness: round_robin_by_project
  model_profile: <经验证的角色与模型映射>
  budget_policy: <用户确认的预算与上限>
```

运行时 API/CLI 计划支持 project register、serve、questions list、memory rebuild/rollback、
doctor 和审计导出；policy publish/revoke 与 ticket pause/cancel/resume/override 已按
本机单 owner 模型接线。Keel 定位为个人单用户工具，HTTP/多租户认证不是待办。
名称在实现契约中统一定稿；不在当前 CLI 帮助里加入尚未实现的命令。

授权更改有独立控制入口与审计，不通过修改工作区 YAML 生效。项目配置错误 fail-closed；jstack 现有交互式 hooks 的宽松降级不能沿用为后台安全策略。

- [ ] 每个声明支持的 Harness 都真实验证：提问、must-stop、等待、恢复、工具边界、无 TTY 运行；缺能力的明确拒绝。
- [ ] [acceptance](./acceptance.md) 全部具备实际结果和证据引用；确定性权限、隔离、竞态与恢复用例全部通过。
- [ ] 真实 GitHub PR/必需 CI 与工作树改动验收通过，结果绑定 target SHA；没有 simulated CI 混入生产。
- [ ] L/XL 至少一条真实多 ticket 路线通过，无双重编排；有待人节点时其他就绪节点持续推进。
- [ ] 人工覆盖、策略撤销、旧 worker 迟到、摘要回滚、外部结果未知均完成故障注入。
- [ ] 数据库与 workflow/blob 备份实际恢复一次；恢复后的待答问题和 outbox 可继续处理。
- [ ] 发布真实支持矩阵、版本/数据迁移/回退说明和当前未覆盖动作。

### 4.2 模型评测与试运行

先准备至少 200 个带条件的历史/合成问题作为初始回归集，覆盖多个项目、授权、冲突、过期与未知事实；另保留按时间和主题隔离的留出集。数字是收集起点，不代表已能证明生产错误率。

模型判断样本由用户既有决定或独立评审标注，不让生成答案的天问给自己打分。回放只使用问题发生时可见资料，不能把后来答案喂进上下文。记录答复是否适用、是否该升级、有无证据和权限；不能只比较文字相似度。

影子模式中对真实请求记录天问候选，与实际用户决定对照；它不增加一轮额外用户确认，也不暗中代批。已有明文决定的复用可先自动启用，新的低影响取舍在该类评测无严重缺陷后启用。

再选择 2–3 个有代表性的项目，在明确授权范围内连续试运行至少 7 天，并至少覆盖 30 个实际适用的代决问题和 5 个真实完成任务；样本不足就继续观察，不按日期自动扩权。人工逐项复核不是长期运行方式，试运行采用抽样和结果回看。

跨项目污染、假冒人工、超授权执行、撤销后执行、错误声称 CI 通过、重复破坏性动作任一出现即停止相关自动能力，分析并补回归；其他项目的安全只读/已验证路径可继续。真实错误率与置信区间按样本报告；不得用 30 个问题声称达到 99.9% 正确率。

### 4.3 指标与告警

| 指标 | 目的 / 初始处理 |
|---|---|
| 天问入口覆盖率 | 系统生成的人工请求必须 100% 有对应 attempt；缺一条视为协议绕过 |
| 代决覆盖率 / 升级率 | 按问题类别和项目拆分；不设牺牲正确性的统一最低自动率 |
| 用户推翻率 / 严重错误 | 分“偏好变化”“旧记录失效”“错误推断”“授权缺陷”；后两类优先修复 |
| 决策时延 | 记录排队/取证/模型/人工分别耗时；建议自动路径 P95 < 90 秒，实测后调预算 |
| 队列年龄 / 租约 / 无进展 | 超时先自动重试或巡检；达到策略上限给明确告警 |
| 外部动作 uncertain | 立即阻断依赖该结果的动作并回查；不得仅重试隐藏故障 |
| 项目级 token/费用/墙钟 | 额度预警、硬上限暂停，未知成本单独呈现 |
| 摘要水位 / epoch / 发布失败 | 失效立即检查，普通整理失败使用可信摘要加增量，不扩大故障面 |

所有延迟和样本数量为目标建议值，不是已经测得的 SLO。服务可用性和恢复目标要以部署环境与演练结果定稿。

## 5. 运行手册与回退

| 事件 | 自动动作 | 人工处理 / 继续条件 |
|---|---|---|
| 天问模型短暂不可用 | 有界退避，保存问题，独立节点继续 | 持续不可用时一次合并告警；不得自动换未批准模型传输项目资料 |
| 数据库不可用 | 停新认领/接纳/许可，保留正在发送动作的关联信息 | 数据库恢复后回查 uncertain 动作，重建队列投影 |
| 一个项目历史冲突 | 只暂停相关问题；天问列冲突来源与推荐 | 用户决定后原子替代旧记录，自动恢复 |
| 用户纠正天问 | 发布新修订，失效旧答案/许可，重算依赖 | 已完成外部动作单独补偿；不篡改旧审计 |
| jstack 新包有缺陷 | 新任务回到上一已验证包；运行中任务保持绑定或暂停 | 修复/兼容性评审后显式迁移，不直接覆盖 provider |
| 摘要回归 | 原子回滚摘要指针，继续读最新撤销/增量 | 重建并通过回归问题集后再发布 |
| daemon 收到 SIGTERM | 停新认领，提交 checkpoint 或等待安全边界 | 重启自动恢复；禁止留下“已答未唤醒”的状态 |
| 远程动作超时未知 | 记 uncertain 并回查，不立即重复 | 无法回查时交天问整理现场再升级；破坏性动作不得猜测成功 |

应用回退保留新表与原始事件；旧二进制不得驱动新类型任务，只服务自己理解的 `legacy-v01`。新工作流可暂停等待兼容版本修复。不会为了回退删除新任务/决定，也不会无损假设把新任务塞回旧状态机。
