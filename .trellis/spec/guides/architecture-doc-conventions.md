# 架构文档约定（Architecture Doc Conventions）

> 来源：`08-22-keel-architecture-framework` 任务。
> 适用于 `docs/` 下的架构文档集，以及任何后续对它的修改。

---

## 为什么需要这套约定

架构文档最常见的失效方式不是写得少，而是**写成散文**：
读起来都对，但没有一处能被机械核对，于是它会随实现慢慢漂移，直到没人再信它。

这套约定的唯一目的：**让文档可以被脚本检查**。

---

## 1. 可寻址 ID

每个会被跨文档引用的概念都必须有一个 ID，且**有唯一的定义处**。

| 前缀 | 含义 | 定义处 |
|---|---|---|
| `S-*` | Task 状态 | `docs/04-state-machine.md` §1.1 |
| `T-NNN` | Task 级转移 | `docs/04-state-machine.md` §2 |
| `C-NNN` | `control_mode` 转移 | `docs/04-state-machine.md` §3.1 |
| `R-NNN` | Run 级转移 | `docs/04-state-machine.md` §4.2 |
| `A-*` | 产物类型 | `docs/06-artifacts.md` §1 |
| `CAP-*` | Harness 能力 | `docs/05-contracts/harness-adapter.md` §1.1 |
| `I*` | 不变量 | `docs/03-domain-model.md` §3 |
| `ADR-NNNN` | 架构决策 | `docs/adr/` |

**规则**：新增一个 ID 必须同时加进它的定义表。
只在正文里提一句而不进表，会产生悬空引用。

**校验**：提取全文所有 `` `前缀-*` ``，与定义表求差集，差集必须为空。

---

## 2. `未验证` 标记 · 最重要的一条

> **任何关于外部系统能力的断言，必须有出处，或显式标注 `未验证`。**

包括：Harness 的 CLI flag、Workflow engine 的语义、模型的能力、第三方 API 的字段名。

**理由**：架构决策建立在这些事实为真之上。
一个听起来合理但实际不存在的 flag，会让整条设计链在实现时才崩塌 ——
而那时已经基于它写了几千行代码。

**踩过的坑**：本任务的推理网关持续 429 / 503，
导致 8 家 Harness 中只查证了 1 家。
正确处置是**留白并标注**，把 ADR 停在 `Proposed`，
而不是"凭印象补齐"让文档看起来完整。

**校验**：`grep -rn '未验证' docs/` 应有输出；
评审时逐条确认每个未标注的外部断言都有出处。

---

## 3. 方法优先级标注

契约中每个接口方法**必须**标注：

| 标注 | 含义 |
|---|---|
| `[v0.1 必须]` | 缺它则最小闭环跑不通 |
| `[可延后]` | 阶段二/三，或仅特定 capability 下需要 |

**没有第三种。** 这是防止契约膨胀成"把未来想得到的方法都先列出来"的硬约束。

**校验**：`grep -c 'v0.1 必须\|可延后' docs/05-contracts/*.md` —— 每个方法都要命中。

---

## 4. 流程走查是证伪测试，不是文档

端到端流程文档（`docs/07-flows.md`）**必须写在契约之后**，
且它的作用是**证伪骨架**，不是复述骨架。

规则：若某条真实流程跨不过既定的架构边界，
**回改架构，不给流程开后门**。

**本任务的实证**：流程走查抓出两个只有走完整条流程才会暴露的结构性缺口 ——
转移守卫没有数据来源（补 `A-StageOutcome`）、
人工接管在 Run 模型中无处安放（补 `HumanAdapter`）。
两者都不是笔误，跳过走查就会在实现到一半时才发现。

---

## 5. 文档依赖顺序

```
术语 → 领域模型 → 状态机 → 产物 → 契约 → 流程（证伪）
                                        ↓
                    跨切面 / 路线 / ADR 可并行；总览最后写
```

两条硬规则：

- **术语必须最先冻结** —— 术语一改，下游全改
- **总览最后写** —— 它是对已定稿内容的摘要；先写会变成又一份 vision doc

---

## 6. 其他

| 约定 | 说明 |
|---|---|
| 语言 | 中文写作；技术术语、接口名、字段名保留英文 |
| 接口签名 | 实现语言拍板前，一律语言中立伪代码 |
| Schema | 落成真实 `.json` 文件供 CI 校验，md 只讲语义与示例，避免两处漂移 |
| 被取代的文档 | 归档 + `superseded` 标注，**不删除**。理由比结论更有保留价值 |
| 缺口追踪 | 每份文档头部标注它满足哪条需求、关闭哪个缺口 |

---

## 7. 提交前自检脚本

```bash
# ID 引用完整性 —— 提取全文 ID，与定义表求差集
# 详见任务 08-22-keel-architecture-framework 的 implement.md Stage 10

# Schema 合法性
for f in docs/schemas/*.schema.json; do python3 -m json.tool "$f" >/dev/null || echo "INVALID $f"; done

# 跨切面禁语
grep -n '以后再说\|后续考虑\|待定' docs/08-cross-cutting.md

# 每份 ADR 都有 Status
grep -L 'Status:' docs/adr/0*.md
```
