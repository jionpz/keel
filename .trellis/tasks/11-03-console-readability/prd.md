# Console 可读性与项目性改进

## Goal

让 `keel console`（`src/cli/console-page.ts`）在不改变「UI 是 Fact Plane 的只读消费者」定位的前提下，
对**第一次看这个页面的人**可读，同时让形态承载项目自己的本体论，而不是通用后台模板。

## Requirements

1. **术语人话层**：任务状态在详情徽章与轨迹上并列显示中文短名与机器码（如 `人工介入` + `S-HUMAN_REVIEW`），
   编号（`S-*` / `T-*`）降为次要视觉层级；侧栏行内空间有限（还要放 control_mode 与任务 ID），
   只显示中文短名，机器码保留在悬浮提示中。术语标签由服务端 `/api/meta` 下发，UI 只消费。
2. **一句话现状**：详情头部在标题下给出一条确定性生成的中文结论，
   说明「现在在哪、为什么停在这、下一步能做什么」，终态给出不可变更提示（I8）。
3. **轨迹按时长可见**：主路径每个阶段在节点内用时长条按最长阶段归一显示停留占比，
   时长文本作为该节点的主视觉；当前非终态阶段显示已停留时长。
   （实测 10 个节点在 ~990px 容器内全部被 min-width 压平，改宽度不可辨识，故用节点内比例条。）
4. **术语表浮层**：页面内可展开的术语说明（状态 / 转移 / Run / 产物 / 事件 / Recipe / Harness / I8 等），
   不引入弹窗库、不依赖外部文档链接。
5. **统一字号与单位**：消除 8.5–9.5px 的核心数据字号；侧栏 `5r` 统一为 `5 轮`；
   正文可读行宽与行高收敛到适合中文的范围。

## Constraints

- 保持零依赖、单文件内联 CSS/JS 的现状；不引入框架、CDN 或构建步骤。
- console 仍然只读：不新增任何写入路径，不改变数据库角色与查询。
- 自动刷新必须继续保留当前 Tab、滚动位置与展开状态。
- 不改变状态机、转移表、事件名等事实层语义；只改呈现。

## Acceptance Criteria

- [ ] 深度页面上任意状态徽章都能同时读到中文短名与机器码，且中文在前。
- [ ] 打开一个人工介入任务时，标题下有一条中文结论，能直接说明「为什么停在这、下一步是什么」。
- [ ] 主路径轨迹中各阶段的停留时长条按比例显示，长阶段明显更长；耗时字号 ≥ 11px。
- [ ] 页面内可展开术语表，覆盖 `S-*`、`T-*`、`I8`、Run、产物/事件、Recipe、Harness 能力等级。
- [ ] 页面无 9px 以下文本；侧栏单位统一为「轮」。
- [ ] `pnpm run lint`、`pnpm run typecheck`、`pnpm test` 通过。
- [ ] 明/暗两种主题下目视检查无回归，1024px 宽度下轨道仍可横向滚动。

## Notes

- 轻量任务，PRD-only。
- 范围限定在 console 呈现层；不触碰 `src/fact`、`src/control` 与状态机定义。
