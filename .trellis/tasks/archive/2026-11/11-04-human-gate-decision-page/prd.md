# 人工闸门决策页：把按钮变成可判断的决策

## Goal

任务停在人工闸门时，页面要能让人**在做决定之前就搞懂三件事**：

1. 这个任务是怎么走到这一步的；
2. 现在到底卡在什么问题、凭什么要人来决定；
3. 每个选项选下去会发生什么（含不可逆的那一个）。

现在页面只给了三个按钮和一行机器码（`T-031 Run 超时升级人工`）。
人不知道自己在批准什么，只能盲点 —— 那比没有按钮更危险。

## 用户与场景

- 用户 = 项目所有者 / 值班人，**只在必要时**打理 AI 运行时，不会每天盯着这个控制台。
- 典型时刻：隔了一天打开控制台，看到一个任务停在「人工介入 9 天 20 小时」。
  他需要在一屏内决定：批准、驳回、还是让它返工。
- 第二个场景：任务停在「待澄清」，需要知道 PM 在问什么，以及不回答会怎样。

## Requirements

**R1 闸门即决策页。** 任务处于 `S-HUMAN_REVIEW` 或 `S-NEED_CLARIFICATION` 时，详情页默认落在新增的
「决策」Tab；其它状态不出现该 Tab。现有四个 Tab 的内容不因此改动。

**R2 先回答「为什么是我」。** 决策页第一块给出停住原因，且必须带证据：

- 一句话结论（人话在前，转移编号 / 事件码降为次要层级）；
- 触发升级的那次 Run：阶段、轮次、状态、`error_kind`、`error_detail`、耗时；
- **同阶段的历次 attempt 轨迹**（第几次、结果、错误、耗时）—— 让「再试一次」这个选项是被证据排除的，
  而不是被忽略的；
- 已停留时长、已花成本与预算上限。

**R3 再回答「我在批准什么」。** 列出这次决定所依赖的既有事实：

- 当前工作分支与基线分支；
- 最近一次成功的产物（RFC 版本 + 摘要、diff 涉及文件数、PR 链接，存在才显示）；
- 每个事实带入口，能跳到对应 Tab 看全文。

**R4 选项即后果。** 每个选项是一张卡，卡片上必须写清：

- **会发生什么**：批准 → 创建分支并派发 `develop` 第 N 轮；返工 → 回到方案讨论、RFC 将被重写；
  驳回 → 进入终态；
- **是否可逆**：驳回标记为终态、不可恢复；
- **需要填什么**：理由输入**内联在卡片里**，不再用 `window.prompt()` 弹窗；
- 提交中 / 成功 / 失败三态；失败时原样显示服务端 `error`。

**R5 澄清闸门同样成页。** `S-NEED_CLARIFICATION` 下：

- PM 判 `unclear` 的 `reason` 与原始需求正文（feedback body）并排可见；
- 若有 `unresolved_questions` 则逐条列出，没有就不臆造；
- 显示澄清 TTL 的**剩余时间**与超时后果（`S-ABANDONED`）；
- 选项 = 补充澄清：多行文本输入 + 提交。

**R6 决策留痕可见。** 决策页底部列出本任务已发生的人工决策（`HumanDecision` 事件：决定、理由、时间）。
连着两次裁决时，人能看见上次为什么那样定。

**R7 写路径不变。** 决策页的提交仍然走 `POST /api/tasks/:id/decide|answer`，
不新增第二个写端点、不复制状态机逻辑、不放宽四道本机校验。

## 非目标

- 不做多用户、不做鉴权、不做审计签名 —— 它仍是本机单人观测面。
- 不做「AI 建议选哪个」的推荐位。
- 不改状态机、不改 `keel decide|answer` 的 CLI 语义。
- 不为决策页新增数据库写路径或缓存表。

## Acceptance Criteria

- [ ] AC1 停在 `S-HUMAN_REVIEW` 的任务打开详情，默认激活「决策」Tab；首屏（1440×900 不滚动）内同时可见：停住原因、失败 Run 的错误、三个选项卡。
- [ ] AC2 三个选项卡各自写明副作用，且文字与转移表一致（approve → `CreateBranch` + `nextRun('develop')`；rework → `nextRun('brainstorm')`；reject → 终态）。
- [ ] AC3 同一阶段的历次 attempt 在决策页可见，含每次的状态 / 错误 / 耗时；只有一次 attempt 时不显示空轨迹区。
- [ ] AC4 「驳回」卡明确标注终态、不可恢复。
- [ ] AC5 理由输入内联在卡片内；页面脚本中不再出现 `window.prompt(` 用于人工闸门。
- [ ] AC6 `S-NEED_CLARIFICATION` 下显示 PM 的 `unclear` 理由、原始需求正文、TTL 剩余时间与超时后果。
- [ ] AC7 提交失败时决策页显示服务端返回的 `error` 原文；成功的显示 `from → to`。
- [ ] AC8 非闸门状态不渲染决策 Tab，其余 Tab 与现有行为逐字不变。
- [ ] AC9 `pnpm run check` 全绿；`console.test.ts` 覆盖决策页渲染的关键断言（闸门状态才出现、选项副作用文案存在、无 `window.prompt(`）。

## Notes

- 术语与文案沿用现有 `statusLabels` / `eventLabels`，不新增第三份状态词表。
- 决策页是**只读事实的重排**，不是新的数据源：所有内容都必须能追溯到 `runs` / `events` / `artifacts` / `timers`。
  任何算不出来的一律不显示，不用占位文案假装有数据。
