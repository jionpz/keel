# 控制台项目页按「少思考」重构信息架构

> 触发:项目页首屏被 6 块平权指标、状态分布图和 6 列表格占满,
> 真正等人工决策的任务反而要用户自己去表格里找。

## Goal

项目页(项目模式侧栏 + 项目详情)从「指标仪表盘」改成「工作页」:
首屏先回答两个问题 —— **有没有事等我?项目整体怎么样?**
让用户不读注解、不做交叉比对,就知道下一步该点哪里。

## Background

- 当前项目详情有 6 个平权指标块(任务 / 运行中 / 待介入 / 已完成 / 轮次 / 成本),
  每块还带一行状态机注解;下面再画一条状态分布条,把同样的计数重复一遍。
- 任务表格按更新时间排序,「人工介入」只是状态徽章的一种,没有行动入口。
- 侧栏每个项目 4 行 9 个信息片段:名字、provider、完整 URL、4 个状态计数、
  任务数/轮次、成本、秒级时间。
- 状态筛选 chip 在项目模式下留在侧栏,视觉上像在筛项目列表,实际筛的是右侧任务表。
- 可写的人工闸门只有 `S-HUMAN_REVIEW` / `S-NEED_CLARIFICATION`;
  点击任务后详情页已会自动落到决策 Tab(`select()` 重置 `tabChosen`)。
- 数据全部来自现有 `GET /api/tasks`;不新增接口、不新增写路径。

## Requirements

- **R1 一句话现状**:项目头部用一句白话说明「几个任务需要你处理 / 几个在跑 /
  几个等待中 / 最近更新」;没有待处理时明确说「没有进行中的任务」。
- **R2 按行动分组**:项目任务按「需要你处理 → 进行中 → 等待中 → 已收尾」分组;
  「需要你处理」固定第一组,行内给行动提示(去决策 / 去回答)。
- **R3 去重**:删除 6 块指标带与状态分布图;同一计数不在同屏用两种视觉重复表达。
- **R4 机器细节降层**:完整仓库 URL 只进 `title`;分支名、单任务成本从列表移除;
  列表时间精确到分钟;项目累计成本只保留一处,按 2 位小数显示。
- **R5 筛选归位**:项目模式下状态 chip 从侧栏移到任务列表上方;侧栏只保留项目搜索。
- **R6 侧栏瘦身**:项目项压到 2 行 —— 名字 + 待处理徽章,任务数/状态摘要/更新时间一行;
  provider 与完整 URL 不再常驻。
- **R7 排序按「是否等我」优先**:有待处理任务的项目排在前面,组内仍按最近更新。
- **R8 口径不新增**:状态标签继续来自 `GET /api/meta`;聚合继续用 `/api/tasks` 现成字段;
  页面不新增状态词表、不新增接口。
- **R9 概览同步**:概览页「项目」块与侧栏使用同一行结构与同一排序。

## Acceptance Criteria

- [ ] 项目页不再渲染 `.proj-stat` 指标带与 `.proj-dist` 分布图。
- [ ] `S-HUMAN_REVIEW` / `S-NEED_CLARIFICATION` 任务出现在首屏「需要你处理」组,
      点击行直接进入决策 Tab。
- [ ] 项目模式下侧栏不显示状态 chip;列表上方的 chip 计数与筛后可见行数一致。
- [ ] 侧栏项目项为 2 行;有待处理任务的项目排在前面。
- [ ] 列表时间不再显示秒;项目页列表不再显示分支名与单任务成本。
- [ ] `pnpm run check` 全绿;`console.test.ts` 增加关键结构断言。

## Out of Scope

- 不新增 API、数据库字段或写路径。
- 不改任务详情页的信息架构。
- 不改概览的统计口径与 14 天活动条。
- 不做移动端新布局;沿用现有 1024 / 900 断点。

## Constraints

- 页面仍是单文件、零构建、零依赖;客户端 JS 继续用字符串拼接。
- 只读约束不变;唯一写路径仍是人工闸门。
- 遵循 `.trellis/spec/frontend/console-guidelines.md` 的视觉纪律:
  无 emoji、无卡片堆、机器码次要层级、窄屏覆盖写在文件末尾。
